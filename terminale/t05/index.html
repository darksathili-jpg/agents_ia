Il dit « Réussi ».
Où est la preuve ?

Un agent peut déclarer avoir corrigé Microduck et réussi tous ses tests. L'orchestrateur ne le croit pas sur parole : il contrôle les fichiers autorisés, la révision testée et les preuves d'un vérificateur indépendant. À la moindre incohérence, la mission est bloquée.

CONTRAT DE CONTRÔLE · PRINCIPE DE NON-CONFIANCE

Les mots ne remplacent pas les vérifications.

01 · SPÉCIFIÉE

Une mission précise les fichiers autorisés, la révision et les tests requis.

02 · EN VÉRIFICATION

L'orchestrateur récupère et confronte les preuves au registre de tests indépendant.

03 · BLOQUÉE

Fichier interdit, résultat échoué, mauvaise révision ou preuve absente : aucun effet.

04 · ATTENTE / VALIDÉE

Une action sensible attend l'humain. Une mission validée peut seulement ensuite agir.

Simulation pédagogique : le « registre indépendant » est un jeu de résultats construits par le banc de tests local. Ce n'est pas une preuve cryptographique ni une vérification de code GitHub réel. Seul le code de l'élève est exécuté par Pyodide dans l'expérience 02.
