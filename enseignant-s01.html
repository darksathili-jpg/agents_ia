Définitions, formalisation et problèmes

1. Une définition est un instrument d’analyse

Le cadre fonctionnel classique de R1 décrit le comportement à partir de perceptions et d’actions. R2 met davantage l’accent sur le contrôle autonome et l’interaction ; parler d’un agent implique alors des choix de délimitation et de capacité. La proposition « tout programme est un agent » peut se défendre avec des frontières très larges, mais perdre presque toute puissance explicative.

Problème enseignant S1 : choisir successivement comme système la fonction decider, son Worker et l’ensemble contrôleur-environnement. Pour chacun, indiquer entrées, sorties, état conservé et décisions effectivement sous contrôle. La fonction seule retourne une chaîne ; la boucle et le moteur lui donnent une portée d’action. Ni le mot « agent » ni l’emploi de Python ne démontrent de compétence générale.

Production attendue : trois schémas de frontière et un paragraphe justifiant le plus utile pour l’activité. Contre-épreuve : peut-on remplacer la politique tout en conservant l’environnement ? Si oui, ce découpage aide à comparer des stratégies plutôt qu’à attribuer leurs propriétés au moteur.

2. Notation progressive et information disponible

Adoptons nos propres conventions. S est l’ensemble des états du monde ; A l’alphabet des actions ; Ω celui des observations. À l’instant t, s_t ∈ S, o_t ∈ Ω, a_t ∈ A. Le modèle déterministe d’environnement est s_(t+1)=T(s_t,a_t) et o_t=O(s_t). Une politique sans mémoire est a_t=π(o_t) ; cela ne suffit à toutes les tâches que sous des hypothèses d’information appropriées. L’action peut néanmoins être légale sans atteindre l’objectif.

Historique h_t=(o_0,a_0,…,a_(t−1),o_t) ; politique générale déterministe a_t=π(h_t). Une réalisation finie emploie une mémoire m_t ∈ M avec a_t=g(m_t,o_t) et m_(t+1)=u(m_t,o_t,a_t). La mémoire peut être un seul bit, un compteur ou une représentation structurée ; stocker un historique ne lui donne pas automatiquement le statut de modèle complet ou correct du monde. [R3]

Pour une politique stochastique, π(a|h_t) désigne une distribution de probabilité sur les actions : valeurs positives ou nulles, somme égale à 1. Cela est distinct d’une transition stochastique P(s'|s,a) ou d’une observation bruitée. Une politique déterministe dans un environnement stochastique reste déterministe ; réciproquement, une marche aléatoire dans une carte fixe ne rend pas cette carte aléatoire.

Dérivation originale pour la formation : si deux états s et s' donnent la même observation o mais exigent respectivement gauche et droite pour réussir immédiatement, une fonction déterministe de o seul choisit la même action dans les deux cas. Elle ne peut donc pas garantir les deux réussites. Une mémoire d’un indice antérieur peut lever l’ambiguïté dans notre exemple ; elle n’élimine pas toute incertitude dans tous les environnements. Le TP03 est un contre-exemple construit, pas une preuve universelle de suffisance d’un bit de mémoire.

3. Objectif, performance, autonomie et rationalité

Une tâche doit spécifier ce qui compte comme réussite et le coût des erreurs. Un objectif terminal n’est pas une fonction de performance complète : deux trajets réussis peuvent différer par la durée, les actions dangereuses ou les ressources. La rationalité classique raisonne relativement à ce critère et à l’information disponible [R1]. L’autonomie se discute selon les choix laissés au contrôleur, les limites d’autorisation et l’éventuel apprentissage ; elle n’efface ni concepteur ni opérateur.

Étude originale S1 : deux stratégies atteignent une sortie. A accomplit 6 déplacements et 2 refus, B accomplit 8 déplacements sans refus. Pour le coût C = déplacements + k × refus, A coûte 6+2k, B coûte 8. A est meilleure si k<1, elles sont à égalité si k=1, B est meilleure si k>1. Les nombres sont ceux d’un dossier d’analyse, pas une mesure du labo où un refus arrête l’épisode. Cette variation rend observable la dépendance au critère ; elle ne prétend pas démontrer une rationalité absolue.

Question de lecture S1 : le critère vient-il de la politique ou de la tâche ? Réponse attendue : il sert à juger un comportement ; sa représentation explicite dans le contrôleur varie. Une politique peut poursuivre implicitement un but sans contenir un objet logiciel objectif.

Production attendue et critique du modèle

Exemple de référence, à discuter après la production personnelle ; il ne constitue pas une réponse unique. Il traite le système réellement présent, sans attribuer au Worker une mémoire qu’il n’a pas.

1. Modélisation explicitée

Tâche : atteindre (6,2) sur une carte fixe 7 × 5. Critères de comparaison : réussite, nombre de commandes et déplacements acceptés. Les obstacles sont ceux du labo ; notamment (2,2) est occupé. Le budget et la convention de refus doivent être spécifiés avant de comparer des programmes.

Monde : position, carte et cible
    → données connues (position, objectif, obstacles)
    → politique Python decider
    → chaîne de commande
    → vérification et application par le moteur
    → position/état/journal observés au pas suivant

Je choisis comme agent le contrôleur en interaction avec ce monde ; la fonction decider est son composant de décision. Le Worker est son mécanisme d’exécution, pas un deuxième robot. Le moteur applique la commande et peut la refuser. La carte et la cible sont connues dans cette expérience : nous ne modélisons pas une caméra ou un vrai robot physique.

Si l’on choisit seulement decider comme frontière, ses entrées sont trois objets et sa sortie une chaîne. Cette description aide à tester le contrat mais ne suffit pas à affirmer que le monde a changé. La frontière contrôleur-environnement permet de comparer plusieurs politiques sur une même transition.

2. Argumentation par programme et trace

La règle locale compare des coordonnées ; elle n’appelle pas de modèle de langage. Elle reçoit les murs, mais n’en déduit pas de détour. Une comparaison de code et d’appels discriminants est une preuve plus pertinente que l’apparence expressive de Microduck.

Tentative Position avant Choix et raison Vérification / effet Position après
1 (0,2) droite, car 0 < 6 (1,2) libre, accepté (1,2)
2 (1,2) droite, car 1 < 6 (2,2) mur, refusé ; épisode bloqué (1,2)

Deux commandes, un déplacement. Le code peut être conforme à l’alphabet et insuffisant pour cette tâche : cette insuffisance ne doit pas être imputée à Pyodide. Un retour constant droite expliquerait ces deux commandes aussi ; pour le départager d’une comparaison, je teste une cible à gauche par appel console. Cet appel n’a pas changé la cible de la grille.

3. Critique du modèle et du critère

Cette trace montre une limite de la règle locale sur une carte, non l’impossibilité de programmer un détour. Une carte connue et une transition déterministe favorisent l’analyse ; elles ne représentent pas la perception bruitée d’un robot réel. Un autre test de réussite, une autre carte ou un droit de réessai peuvent modifier le classement des stratégies.

Je ne confonds pas autonomie opérationnelle et succès : en mode automatique, le contrôleur peut enchaîner des choix sans que l’humain indique chaque commande, tout en échouant. Le mode pas à pas suspend l’exécution pour l’observation pédagogique ; il ne remplace pas la politique par une décision manuelle. Le fait qu’une action ait été expliquée dans le journal ne prouve pas une conscience ou une justification interne de LLM.

4. Transposition et contrôle des acquis

Première : distribuer le repère x/y et faire remplir les quatre dernières colonnes de la trace avant de discuter la définition. Terminale : demander un contre-test qui départage deux fonctions et une spécification de retour. Je valide la compréhension si l’élève distingue observation, commande et effet, justifie une limite et propose un test susceptible d’invalider sa première explication.

Si l’élève écrit « le robot décide de rester car il voit le mur », je demande : « Quel return du code produit cela ? Qui vérifie ensuite la candidate ? » Dans ce cas la commande reste droite ; c’est la transition qui refuse. Une réponse corrigée par cette lecture vaut davantage qu’un vocabulaire appris sans trace.

Transposition et lecture critique

Comparer R1 et R2 : préciser le cadre retenu, puis un cas frontière. Le contrôleur, la fonction et le Worker sont des frontières différentes ; la réponse attendue doit annoncer ce qui est observé et ce qui est effectivement commandé. Une lecture de synthèse ne remplace pas la contre-épreuve du programme.

Corrigés S01 et remédiations

Diagnostic : droite, gauche, arrêt ; print affiche mais ne remplace pas return ; la coordonnée suivante est (3,1). Le diagnostic ne doit pas absorber les quarante minutes de TP.

def decider(position, objectif, obstacles):
    x, y = position
    gx, gy = objectif
    if x < gx:
        return "droite"
    if x > gx:
        return "gauche"
    if y < gy:
        return "bas"
    if y > gy:
        return "haut"
    return "arrêt"

assert decider((0, 2), (2, 2), []) == "droite"
assert decider((4, 2), (2, 2), []) == "gauche"
assert decider((2, 2), (2, 2), []) == "arrêt"
assert decider((2, 2), (2, 1), []) == "haut"
print("S01_CORRECTION_OK")

Cette politique reçoit les murs mais ne recherche pas de détour : le deuxième pas est refusé sur cette carte. Le corrigé n’est pas une solution générale de navigation. Dans le transfert porte/clé, exiger observations, actions, un test et une question sur une information qui disparaît. Au bilan, vérifier la justification et le test proposé ; les réponses libres ne sont pas automatiquement notées.
